## [HIGH] 비밀번호 MD5 저장 (기본값)

- 기본 저장 방식은 원본과 같은 salt 없는 md5 다. MD5 는 레인보우 테이블과 GPU 무차별 대입에 약하다.
- `$service['passwordHash']` 를 `'multi'`·`'migrate'` 로 두면 password_hash 로 저장한다. 되돌리기 전 확인 사항은 MIGRATION 5·6절.

## [LOW] 정적 자산 잔여 위험

- TinyMCE 는 7.9.3 으로 올렸다. 커스텀 플러그인(`TTMLsupport`·`codemirror`)은 7.x API 로 고쳐 썼다.
- Bootstrap 3.4.1(스킨 lucid·periwinkle)은 유지보수가 끝났다. carousel·button `data-loading-text` XSS 는 4.x 에서만 고쳐졌으며, 두 스킨은 이 기능을 쓰지 않는다.
- reCAPTCHA `api.js`·Google Maps JS 는 응답이 바뀌는 동적 스크립트라 SRI 를 붙일 수 없다.
- jQuery 3.3 에서 deprecated 된 API(`jQuery.isFunction`·`jQuery.proxy`·`bind`/`unbind`·`delegate`/`undelegate`)는 3.7.1 에서 동작하지만 jQuery 4 로 옮길 때 정리해야 한다.
- 덮어써 올린 설치에 남는 옛 파일(쓰지 않는 정적 자산, OpenID 2.0 라이브러리 `library/contrib/phpopenid/`, 웹에서 직접 열리는 jpgraph `plugins/StatGraph/count/`, CodeMirror 의 node.js 전용 파일)은 루트의 `cleanup_legacy_assets.php` 로 지운다. 내용이 바뀐 파일은 건너뛰므로 직접 지운다(MIGRATION 3절).
- CodeMirror 의 node.js 전용 파일(`package.json`·`bin/source-highlight`·`addon/runmode/runmode.node.js`)은 편집기가 쓰지 않는데 저장소 의존성 경고의 대상이 되어 r4 에서 뺐다. 정리 스크립트로 지운 뒤에는 ED_tinyMCE 플러그인이 무결성 검사에 한 번 막히므로 플러그인 화면에서 '다시 검사하고 풀기'를 한다(MIGRATION 10절).

## [NOTE] PHP 5.5 판 한계

PHP 5.5 ~ 7.3 은 PHP 프로젝트의 보안 지원이 끝난 판이다. 이 판은 아래 기능을 호환 구현으로 맞췄지만 PHP 5.5·5.6 에서는 다음 차이가 남는다.

- 다른 사이트로의 HTTPS 요청(피드·트랙백·핑·OpenID Connect·소셜 로그인·IMAP/POP3): PHP 5.5 는 인증서의 CN 만 확인하고 subjectAltName 은 보지 않는다 — SAN 에만 이름이 있는 인증서는 연결이 실패한다(안전한 쪽). 시스템 CA 묶음을 스스로 찾지 못하는 호스팅은 `config.php` 에 `$service['tls_cafile']`(또는 `tls_capath`)를 적어야 HTTPS 요청이 된다(적지 않으면 연결 거부).
- 난수: `/dev/urandom` 을 읽을 수 없고(`open_basedir` 등) mcrypt 확장도 없으면 로그인·폼 토큰을 만들지 못한다(약한 난수로 내려가지 않음).
- PDO MySQL: PHP 5.5.0~5.5.20 은 다중 문장 차단(`PDO::MYSQL_ATTR_MULTI_STATEMENTS`)이 없다. DB SSL 연결의 서버 인증서 검증(`$database['ssl_verify']`)은 이를 지원하지 않는 PHP 판에서 켜면 연결하지 않는다.
- PHP 5.x 에서는 이미지 처리·스킨 해석 중 PHP Fatal 오류를 잡지 못해 그 요청이 멈춘다(7.x 는 잡고 진행).
- 저장된 값에 객체가 들어 있으면 PHP 5.x 는 값을 읽지 않고(false), 7.x 는 객체를 만들지 않은 채 읽는다 — 둘 다 객체 주입은 막힌다.
- 서버 설정 저장: PHP 5.x 는 문법 검사 대신 토큰 구조로 `config.php` 를 확인한다(깨진 원문이면 저장하지 않음).
- 이모지는 MySQL 5.6+·MariaDB 10.0+ 에서만 저장한다.

## 해소 항목

원본 Textcube 1.10.10 대비 보안 변경을 성격별로 나눈다. **[패치]** 는 원본에 있던 취약점·결함을 고친 것이고, **[도입]** 은 원본에 없던 방어 기능·설정을 새로 넣은 것이다(선택 기능이면 '선택'이라고 적는다). 항목 끝의 (r1)·(r2)·(r3)·(r4)는 해소한 판이다.

### 인증·세션

- [패치] 로그인할 때 세션 ID 를 바꾸지 않아 로그인 데이터가 이전 익명 세션에 기록되던 세션 고착을 고쳤다. 로그인 시 세션 ID 를 새로 발급한다. (r3)
- [패치] `?TSSESSION=` 같은 URL 값으로 세션을 고를 수 있던 경로와 `/login?session=` 으로 임의 세션 쿠키를 심던 경로를 막았다. (r3)
- [패치] memcached 세션 ID 를 예측하기 쉬운 `rand()` 로 만들던 것을 CSPRNG 로 바꿨다. (r1)
- [패치] 임시 비밀번호·DB 세션 ID·인증 토큰을 만들 때 예측 가능한 난수를 쓰던 것을 CSPRNG 로 바꾸고, 비교에는 시간차 공격을 막는 `hash_equals()` 를 쓴다. (r1, r3)
- [패치] 초대 메일 링크·임시 암호 같은 인증 토큰에 만료가 없고 여러 번 쓸 수 있던 것을 고쳤다. 토큰은 만료 시각이 지나면 거부하고 한 번 쓰면 폐기한다. (r3)
- [도입] 로그인 실패와 비밀번호 확인 실패에 계정별 횟수 한도를 두어 한도를 넘으면 잠근다. (r3)
- [도입] 같은 접속 IP 에서 로그인 실패가 반복되면 그 IP 의 로그인을 잠근다. (r3)
- [도입] 블로그 API(XML-RPC) 로그인 시도 횟수를 제한한다. (r3)
- [도입] 비밀번호를 salt 없는 md5 대신 `password_hash` 로 저장하는 방식을 `$service['passwordHash']` 설정으로 고를 수 있게 했다. 기본값은 원본과 같은 md5 이며 선택 기능이다. (r3)
- [도입] 이메일·API 키·블로그 주소 변경, 소셜 연결·해제, 임시 암호 발급, 소유자 변경 같은 민감한 설정을 바꿀 때 비밀번호를 다시 확인한다. (r3)
- [패치] 블로그 API 의 API 키 자리에 계정 비밀번호를 받아, 블로그 구성원이 아닌 계정도 인증되던 문제를 고쳤다. (r3)
- [패치] OpenID 로 쓴 댓글이 모두 같은 고정 비밀번호를 갖던 문제를 고쳤다. (r3)
- [패치] 팀블로그 화면에서 다른 구성원의 인증 토큰과 저장된 비밀번호 해시가 보이던 문제를 고쳤다. 초대 링크는 초대한 사용자에게만, 아직 로그인하지 않은 계정에만 표시한다. (r3)
- [패치] Moblog 가 허용 발신자를 부분 문자열로 비교하고 목록 밖 메일도 MMS 헤더만으로 공개 글에 올리던 문제를 고쳤다. 이제 정확히 일치한 발신자만 허용하고, 그 밖의 MMS 메일은 비공개 새 글로 올린다. From 헤더 위조는 메일 서버 쪽 확인이 필요해 막지 못한다. (r3)
- [패치] Moblog 의 POP3/IMAP 연결이 TLS 인증서의 서버 이름을 검사하지 않던 문제를 고쳤다. (r3)
- [패치] DB 세션과 memcached 세션이 접속 주소를 확인하지 않던 문제를 고쳤다. (r3)
- [도입] memcached 연결에 실패하면 세션 저장소를 DB 로 대신하고, 대신 쓰는 저장소에서도 세션 ID 주입·고정과 다른 주소 재사용을 막는다. (r3)
- [패치] 쿠키에 `HttpOnly`·`SameSite`·`Secure` 속성이 없던 것을 고쳤다. (r2)
- [도입] 원본이 지원하던 OpenID 2.0 은 지원이 끝나 제거하고, OpenID Connect(OIDC) 로 다시 구현했다. 지원이 끝난 OpenID 2.0 라이브러리(phpopenid)도 제거했다. 소셜 로그인(카카오·네이버·Facebook)은 통합 플러그인으로 새로 넣었다. (r2, r3)
- [도입] 소셜 계정으로 쓰는 댓글은 서버가 소셜 로그인 여부를 확인하고 글쓴이 이름·비밀번호를 정한다. 화면에서 보낸 이름·비밀번호는 쓰지 않는다. (r3)
- [도입] PHP 5.5·5.6 에서도 세션·CSRF·인증 토큰을 안전한 난수원으로 만들고(없으면 발급 거부), 토큰 비교는 상수 시간으로 한다. 로그인할 때 세션 ID 를 바꾼다. PHP 7.2 이하에서도 쿠키에 HttpOnly·SameSite·Secure 속성을 붙인다. (r4)

### CSRF·요청 형식

- [도입] 관리 화면 요청에 블로그별 CSRF 토큰을 검사한다. 경로 모드에서 블로그를 판정할 수 없는 Referer 를 통과시키는 틈도 없앴다. (r3)
- [패치] 상태를 바꾸는 GET 요청을 POST 로 바꿨다. 플러그인 켜기·끄기 GET 과 CL_Moblog 로그 지우기도 CSRF 검사와 함께 바꿨다. (r3)
- [패치] 플러그인 관리 화면 등 일부 관리 화면에 CSRF 검사가 빠져 있던 것을 보강했다. (r2, r3)
- [도입] 관리 화면이 다른 사이트의 프레임 안에서 열리지 않게 `X-Frame-Options` 로 클릭재킹을 막는다. (r3)
- [도입] 입력 변수 수가 너무 많거나(413) 허용하지 않는 Content-Type(415)이거나 형식이 잘못된(400) 요청을 일찍 거부한다. (r3)

### SQL 삽입

- [패치] 원본의 수동 escape 로 이어 붙이던 주요 쿼리를 준비 문장(prepared statement)으로 바꿨다. (r1)
- [패치] 사용자 찾기(`/control` suggest)를 비롯해 위도·경도, 분류 id, 블로그 소유자·사용자 삭제, 세션 정리, 블로그 설정 지우기, slogan 중복 검사, 게스트 세션 같은 여러 화면의 SQL 삽입 가능 지점을 정수 변환·escape·바인딩으로 막았다. (r2, r3)
- [패치] DB 어댑터(MySQL 외 PostgreSQL·SQLite3·Cubrid)에서 준비 문장이 제대로 동작하지 않거나 값을 SQL 에 직접 넣던 부분을 드라이버 바인딩으로 고쳤다. (r3)
- [패치] PostgreSQL·Cubrid 에서 IP 필터 조건 값을 큰따옴표로 넣어 질의가 늘 실패해 손님 IP 차단이 꺼져 있던 문제를 고쳤다. 값은 작은따옴표 리터럴로 escape 한다. (r4)
- [패치] SQLite 3.44 미만에서 스팸 필터 질의(`CONCAT`)가 실패해 이름·홈페이지·본문 차단과 화이트리스트가 적용되지 않던 문제를 고쳤다. (r4)
- [패치] PostgreSQL·Cubrid 어댑터의 `CONCAT` 변환이 따옴표 수의 제곱만큼 시간이 걸려 긴 입력 하나로 요청이 오래 걸리던 문제를 고쳤다. (r4)

### XSS·출력 escape

- [패치] 사용자 찾기 화면과 관리 화면(댓글·알림·글 화면, 사이드바, 대시보드)에서 요청 값을 그대로 출력하던 반사형 XSS 를 출력 인코딩으로 막았다. (r2, r3)
- [패치] 리퍼러·Moblog 같은 외부 값이 저장되었다가 출력되는 저장형 XSS 와 블로그 머리(head)의 JS 문자열 출력을 escape 했다. (r3)
- [패치] GoogleMap 플러그인의 위치·제목·마커 문자열 출력을 escape 했다. (r3)
- [패치] RSS·ATOM 피드 출력에 XML escape 를 적용했다. (r3)
- [패치] Jukebox 모바일 출력, 첨부 동영상 바인더, 편집기가 삽입하는 주소의 출력을 escape 했다. (r3)
- [패치] 관리 화면에 표시하는 로그인 ID 를 escape 했다. (r3)
- [패치] 리더 본문의 HTML 을 블랙리스트 필터 대신 허용 목록 방식의 정화기로 걸러 낸다. (r3)
- [패치] 휴지통 화면의 분류 선택 상자가 분류 이름을 JS 문자열에 HTML escape 만 거쳐 넣어, 역슬래시 꼴(`\x3c` 등)로 쓴 이름이 관리자 화면에서 태그로 풀리던 저장형 XSS 를 고쳤다. 분류를 만들 수 있는 편집자 이상의 입력이다. (r4)
- [패치] 분류 body id 가 escape 없이 스킨 `<body id>`·글 목록 class 로 나가던 문제를 고쳤다. 저장할 때 영문·숫자·`_`·`-` 20자 이하만 받고(백업 가져오기의 분류 body id·공개 값도 같은 검사), 출력할 때도 escape 한다. (r4)

### 역직렬화·객체 주입

- [패치] 플러그인 설정을 읽을 때 저장된 값에 든 객체가 만들어져 코드가 실행될 수 있던 문제를 막았다. 배열만 복원한다. (r3)
- [도입] PHP 5.x 에서도 저장된 값에 객체가 들어 있으면 읽지 않는다(PHP 7 의 `allowed_classes` 를 쓸 수 없는 판). (r4)

### 서버가 보내는 요청(SSRF)

- [패치] 리더 이미지 프록시·백업 웹 가져오기·표지 플러그인·피드와 OPML 가져오기가 내부 주소로 요청을 보낼 수 있던 SSRF 를 막았다. 공통 요청 함수에서 주소를 검사한다. (r3)
- [패치] 댓글 답글 알림·트랙백·ping 처럼 사용자가 지정한 주소로 서버가 요청하는 기능이 내부 주소로 향하지 못하게 했다. (r3)
- [패치] 바깥 요청이 응답 크기·시간에 상한이 없고 리다이렉트로 검사를 피할 수 있던 문제를 고쳤다. 상한과 리다이렉트 재검사를 둔다. (r3)
- [도입] PHP 5.5 에서도 다른 사이트로 보내는 HTTPS 요청의 인증서를 검증한다(CA 묶음 필요, [NOTE] 참조). (r4)

### 파일·경로·업로드

- [패치] 서버에 만든 백업 파일이 웹에서 직접 내려받아지던 문제를 고쳤다. (r3)
- [패치] 첨부 경로 순회와 임시 파일(pickle) 경로 순회로 의도하지 않은 파일을 읽거나 쓸 수 있던 문제를 고쳤다. 백업 가져오기의 첨부 경로 검사와 도움말 화면의 언어 값을 이용한 경로 순회도 고쳤다. (r2, r3)
- [패치] 설치 마법사가 `config.php` 에 값을 그대로 써서 코드가 주입될 수 있던 문제를 고쳤다. (r3)
- [패치] 서버 설정을 `config.php` 에 쓸 때 따옴표·역슬래시를 escape 하지 않아 파일이 깨지거나 코드가 주입될 수 있던 문제를 고쳤다. (r3)
- [패치] 플러그인 locale 파일과 플러그인·스킨 `index.xml`, `.user.ini` 를 웹에서 직접 열 수 있던 것을 막았다. (r3) `.user.ini` 차단은 `AllowOverride FileInfo` 만 허용한 Apache 에서도 동작하는 규칙으로 바꾸고, 경로 뒤에 PATH_INFO 가 붙은 요청과 설치 마법사의 IIS 템플릿까지 같은 범위로 막는다. (r4)
- [패치] `plugins/` 와 `attach/` 아래에 올린 PHP 가 실행되던 문제를 중간 확장자(`.php.jpg` 형태)와 `php` 숫자 확장자까지 포함해 막았다. (r3)
- [패치] 첨부로 올린 SVG 의 스크립트·이벤트 속성·외부 참조·`attr(` 를 걸러 내는 정화를 적용하고, SVG 변환 시간에 한도를 둔다. (r3)
- [패치] 첨부 응답에 안전한 헤더를 붙이고, `.html` 첨부가 인라인으로 실행되던 문제를 고쳤다. (r3)
- [패치] 블로그 API 가 옛 실행 이름으로 첨부를 저장할 수 있던 문제를 고쳤다. (r3)
- [패치] 이미지 리사이저의 크기 인자를 검사하지 않아 요청 하나로 메모리가 소진되던 문제를 고쳤다. (r3)
- [도입] PHP 5.x 에서 서버 설정을 저장할 때 `config.php` 가 빈 파일로 덮이지 않도록 원문·결과의 구조를 확인한다. (r4)

### 헤더·프록시·Host

- [패치] `Client-IP`·`X-Forwarded-For` 헤더를 무조건 믿어 접속 IP 를 위장할 수 있고, 그 값이 SQL 에 들어가던 문제를 고쳤다. 신뢰할 프록시에서 온 요청에만 헤더를 적용한다. (r3)
- [도입] 서비스 주소의 스킴을 정할 때 `X-Forwarded-Proto` 는 신뢰할 프록시를 거친 연결에서만 반영한다. (r3)
- [패치] Host 헤더를 위조해 주소·페이지 캐시·피드 캐시·메일 링크를 오염시킬 수 있던 문제를 고쳤다. Host 를 검증한다. (r3)
- [도입] 서비스 주소가 설정돼 있으면 소셜 로그인 콜백 주소를 그 호스트로 고정해 위조 Host 로 만들 수 없게 한다(`//호스트`·`http(s)://` 형식 모두, 도메인 모드 블로그 제외). (r3)
- [패치] 로그인·OpenID·소셜 로그인의 되돌아갈 주소가 외부 주소로 바뀌던 오픈 리다이렉트를 막았다. (r3)
